# aamp design

aamp is a local-music player for Android Auto. Its main job is to turn Gemini voice requests into the right queue, album requests in particular, for music files already on the phone. It targets Android 17 only and is sideloaded onto one device. [2026-10-29-gemini-voice-routing.md](2026-10-29-gemini-voice-routing.md) explains why it exists and which voice path it relies on.

## Goals

- "Play the album X by Y" plays album X from its first track; artist, song and shuffle requests behave predictably.
- Android Auto browsing by album, artist and song, with artwork and in-app search.
- Low latency from voice request to first audio, especially from a cold process; low memory and battery use.
- Every voice request the app receives is logged with its raw query and hints.

## Non-goals

- Gemini on the phone outside the car: no route exists for non-partner apps.
- Streaming services, network sources and casting.
- Play Store distribution and Android versions below 17.
- Tag editing and playlist editing.

## Platform and toolchain

| Item | Choice |
|---|---|
| Android | minSdk, targetSdk and compileSdk 37; SDK platform `android-37.2` |
| Language | Kotlin 2.4.21 (K2 compiler) |
| Build | Gradle 9.8.2 wrapper; Android Gradle plugin 9.5.0 with built-in Kotlin, whose bundled 2.2.10 compiler is replaced by 2.4.21 through the Kotlin plugin declaration in the root build file; JDK 27 host; bytecode target 21 (Kotlin's `invokedynamic` type switches dex and run correctly on API 37) |
| Media | Media3 1.11.1: `media3-exoplayer` and `media3-session` only |
| Concurrency | kotlinx-coroutines 1.11.0 with the Guava bridge for Media3's `ListenableFuture` |
| Phone UI | Platform `android.widget`; no AppCompat, Material or Compose |
| Application id | `dev.cyh.aamp` |

Media3 is the practical way to serve Android Auto, which still connects through the legacy `MediaBrowserService` protocol that Media3 translates. The alternative, the platform `MediaBrowserService` and `MediaSession` with a player written on `MediaCodec` and `AudioTrack`, saves no CPU because decoding runs in the platform codec either way; it would mean reimplementing gapless playback, audio focus, offload and Android 17's background audio rules. Compat libraries exist to support older Android versions, so with minSdk 37 they are dead weight. The phone screen is a status page, too small to justify Compose's runtime and startup cost.

## Architecture

One process. Nothing on the Android Auto path loads UI classes.

| Component | Responsibility |
|---|---|
| `AampApplication` | Holds the process-wide `Library` and `VoiceLog`, both created on first use. |
| `PlaybackService` | `MediaLibraryService`. Owns the `ExoPlayer` and `MediaLibrarySession`; Android Auto binds here. Holds the `mediaPlayback` foreground service while playing. |
| `LibraryCallback` | `MediaLibrarySession.Callback`. Browse tree, search, and turning requests into queues. |
| `Library` | Loads the `LibrarySnapshot` from the persisted file or MediaStore; watches MediaStore for changes. |
| `SearchIndex` | Normalized keys and posting lists over the snapshot. |
| `VoiceRequestParser`, `QueueResolver` | Turn `(query, extras)` into a `PlayRequest`, then into a queue and start index. |
| `VoiceLog` | Size-capped log of every incoming request, its parse, outcome and latency. |
| `ArtworkProvider` | Read-only `ContentProvider` serving scaled album art to Android Auto. |
| `MainActivity` | Permission, library status, rescan and the voice log. |
| `PlayFromSearchActivity` | Replays a voice request from an adb `MEDIA_PLAY_FROM_SEARCH` intent through the same session path, for testing without a car. Gemini never sends this intent. |

A voice request flows like this:

1. Gemini resolves the speech, and Android Auto calls `playFromSearch(query, extras)` on the session.
2. Media3 wraps it in a `MediaItem` whose `RequestMetadata` holds `searchQuery` and `extras`, then calls `onSetMediaItems` (checked in the Media3 1.11.1 source, `MediaSessionLegacyStub.onPlayFromSearch`).
3. The callback logs the request, parses it, waits a bounded time for the library if it is still loading, and resolves a queue on the library dispatcher.
4. It returns `MediaItemsWithStartPosition`; Media3 sets, prepares and plays on the main thread.

Media3 advertises `ACTION_PLAY_FROM_SEARCH` and `ACTION_PREPARE_FROM_SEARCH` whenever the player allows `COMMAND_SET_MEDIA_ITEM`, idle state included. Removing that command would break voice requests.

## Voice requests

### Parsing

When `android.intent.extra.focus` is present, the hints decide the request type. Otherwise the raw query is parsed, after stripping a leading "play", "shuffle" or "listen to" and a trailing "on aamp":

| Spoken form | Request |
|---|---|
| "(the) album X (by Y)", "X album (by Y)" | Album |
| "songs by Y", "music by Y", "artist Y" | Artist |
| "(the) song X (by Y)", "track X (by Y)" | Song |
| "X by Y" | Ambiguous |
| "X" | Ambiguous, or Artist if X matches an artist exactly |
| empty | Resume |

"By" is split at its last occurrence, and only when the right-hand side matches an artist, so titles such as "Stand by Me" survive. A leading "shuffle" sets shuffle on the resulting queue.

### Resolution

| Request | Queue |
|---|---|
| Album | The album from disc 1, track 1; shuffle off |
| Artist | Every track by the artist (album artist or track artist), shuffled |
| Song | The song, then the rest of its album |
| Ambiguous | An artist when it scores at least as well as any album or song; otherwise the album when it scores no more than 0.05 below the best song, else the song. Gemini removes the word "album" from requests, so an album and its same-named title track must resolve to the album |
| Resume | The last saved queue; if none, the whole library shuffled |
| No match above threshold | Nothing plays; the session reports a non-fatal error naming the unmatched text so Android Auto can show it |

### Normalization

- Unicode NFKC, then lowercase with `Locale.ROOT`; combining marks stripped after NFD, so "Motörhead" matches "motorhead".
- Punctuation and symbols removed. "&" and "+" become "and"; apostrophes join without a space ("Kill 'Em All" becomes "kill em all"); leading dots disappear ("...And Justice for All" becomes "and justice for all").
- Whitespace collapsed; a leading "the" is optional on both sides.
- Bracketed edition suffixes ignored for matching: remaster, remastered, deluxe, edition, version, anniversary, expanded, bonus.
- Scripts written without spaces (Han, Hiragana, Katakana) are tokenized as character bigrams.
- Planned: digits and number words treated as equal, since speech recognizers produce either.

### Scoring

An inverted index maps each token to a sorted `IntArray` of album, artist or track ids, so only candidates sharing a token are scored; when none of those scores 0.9, every entry is scored. Scores, from strongest: exact normalized match; the whole query as a run of words inside the entry (partial names, 0.6 to 0.9); word alignment, where the entry's words are matched in order against the query's with partial words ("just" for "justice") and near misses ("metalica") counting, scored as F1 of matched weight over both lengths (up to 0.95); character-trigram similarity for a misrecognized single word (up to 0.8). The F1 form keeps a one-word title inside a long query low: Gemini's "and just for all my intelligents" scores 0.73 for "...And Justice for All" and 0.27 for Radiohead's "Just". When an artist is given, the score is weighted by artist similarity against both album artist and track artist; a missing artist costs nothing. "X by Y" and "X my Y" are both tried as title and artist when Y matches a library artist. Thresholds and margins are constants, to be tuned with a test corpus generated from the device's own library.

## Library

The source is `MediaStore.Audio.Media` on the external volume with `IS_MUSIC != 0`, reading `_ID`, `TITLE`, `ARTIST`, `ARTIST_ID`, `ALBUM`, `ALBUM_ID`, `ALBUM_ARTIST`, `COMPILATION`, `CD_TRACK_NUMBER`, `DISC_NUMBER`, `YEAR`, `DURATION`, `GENRE` and `DATE_ADDED`. MediaStore has already parsed the tags, so aamp never opens files for metadata. If MediaStore turns out to mishandle album artists, compilations or disc numbers on the real library, a dedicated tag reader becomes a later milestone.

The `LibrarySnapshot` is immutable and stored as struct-of-arrays: primitive arrays for ids, durations and track positions; tracks sorted by album, disc and track; albums and artists as index ranges into the track arrays; normalized search keys precomputed. Its size is proportional to the library, and a rescan replaces it atomically instead of growing it.

The snapshot persists as a versioned binary file in `noBackupFilesDir`. Its header records the format version, `MediaStore.getVersion` and `MediaStore.getGeneration` for the external volume. At cold start both values are read, which is cheap; when they match, the file is loaded with one sequential read. When they do not, the stale snapshot serves requests while a rescan runs in the background, then is swapped. While the process runs, a debounced `ContentObserver` on the audio collection triggers the same check.

Without `READ_MEDIA_AUDIO`, browsing and voice requests return a permission error whose message asks the user to open aamp on the phone.

MediaStore does not index files inside folders whose names start with a dot, because Android treats them as hidden. An album stored as `Music/Metallica/...And Justice for All/` is therefore invisible to aamp and to every other MediaStore-based player, while players with their own file scanner (Poweramp) still see it. The fix today is renaming the folder; the tags still carry the real album name. Detecting such folders and either warning on the phone screen or scanning them directly is milestone 2 work.

## Playback

- A custom `RenderersFactory` creates only `MediaCodecAudioRenderer`, so R8 removes video and text rendering code.
- A custom `ExtractorsFactory` creates only the containers in the library: FLAC, MP3, MP4 (AAC and ALAC), Ogg (Vorbis, Opus, FLAC) and WAV.
- Audio attributes `USAGE_MEDIA` and `AUDIO_CONTENT_TYPE_MUSIC`, with ExoPlayer handling audio focus and pausing when headphones disconnect.
- `C.WAKE_MODE_LOCAL`, since every source is a local file.
- Gapless playback through ExoPlayer's encoder delay and padding handling.
- Audio offload enabled with gapless support required, so the audio DSP decodes while the CPU sleeps. Whether offload engages while audio is routed to Android Auto is an open question.
- The queue (track ids, index, position) is saved to a small binary file on pause, stop and track change, and restored through `onPlaybackResumption`.

Android 17 hardens background audio: for apps targeting API 37, background playback and audio focus need a foreground service with while-in-use capability, and failures are silent. `MediaLibraryService` runs the `mediaPlayback` foreground service while playing, and Google expects Media3 session apps to be unaffected. Whether a voice request arriving through Android Auto while aamp is in the background satisfies the while-in-use rule must be tested first, with `adb shell cmd audio set-enable-hardening throw` and `adb shell dumpsys audio`.

## Android Auto browse tree

- Root tabs: Albums (grid), Artists (list), Songs (list). Android Auto typically shows up to four root tabs.
- Ids: `albums`, `artists`, `songs`, `album:<albumId>`, `artist:<artistId>`, and `track:<trackId>@<context>`, where the context (`album:<albumId>`, `artist:<artistId>` or `songs`) decides the queue built when that track is played.
- Paging requests are honoured. Android Auto limits list length while driving, so the Songs tab mainly serves search and shuffle.
- `onSearch` and `onGetSearchResult` use the same index, with results grouped as albums, artists and songs through `EXTRAS_KEY_CONTENT_STYLE_GROUP_TITLE`. Media3 advertises search support automatically.
- Artwork URIs point at `ArtworkProvider`, which scales album art with `ContentResolver.loadThumbnail` into an LRU cache bounded by bytes.

## Phone screen

One activity built from platform widgets: permission state and grant button; track, album and artist counts with last scan time and duration; a rescan button; the most recent voice requests with raw query, hints, parsed request, outcome and latency; recent process exit reasons from `ApplicationExitInfo`.

## Performance

Measurements come from release builds on the device; debuggable builds disable most ART optimizations and are not representative.

- **Shrinking.** R8 full mode with resource shrinking. No reflection, no `kotlin-reflect`, no reflection-based serialization; binary formats are hand-written.
- **Compilation.** A baseline profile and startup profile, generated with the `androidx.baselineprofile` plugin and a macrobenchmark module, cover service cold start, a voice request and browsing. `profileinstaller` applies them on sideload. Because aamp runs on one device, full AOT (`adb shell cmd package compile -m speed -f dev.cyh.aamp`) is also measured against the profile-guided build.
- **Threads.** Media3 session and player calls stay on the main thread and never block. MediaStore scans run on one serial I/O dispatcher; matching and media item building run on `Dispatchers.Default`. Snapshots are immutable, so the hot path takes no locks.
- **Memory.** Android 17 kills processes that exceed a memory limit derived from device RAM; the exit description contains `MemoryLimiter:AnonSwap`. The index stays compact, the artwork cache is bounded, and exit reasons are shown on the phone screen.
- **Diagnostics.** Android 17's `ProfilingManager` trigger `TRIGGER_TYPE_COLD_START` captures a call-stack sample and system trace of a cold start.

Initial budgets, to be revised after the first measurements:

| Path | Budget |
|---|---|
| Process start to session ready | 150 ms |
| Snapshot load, 10,000 tracks | 30 ms |
| Voice request to resolved queue, warm | 10 ms |
| Voice request to first audio, cold process | 400 ms |
| Voice request to first audio, warm process | 150 ms |
| Index heap, 10,000 tracks | 8 MB |

## Kotlin conventions

- Stable Kotlin 2.4 language features are used freely: context parameters, explicit backing fields, guard conditions in `when`, data-flow-based exhaustiveness, non-local `break` and `continue`, multi-dollar interpolation and nested type aliases. Experimental features (collection literals, name-based destructuring, explicit context arguments) need a recorded reason in this document.
- Request and outcome types are sealed interfaces matched exhaustively. No `!!`. Exceptions never cross Media3 callbacks; failures become failed futures or session errors.
- Value classes wrap ids at API boundaries; the index uses primitive arrays, because value classes box inside generic collections.
- The library and voice log live in a process-wide scope owned by `AampApplication`; the playback service has its own scope, cancelled in `onDestroy`. Media3 callbacks answer through the Guava bridge (`future {}`).
- `android.util.Log` with fixed tags: `Aamp`, `AampVoice`, `AampLibrary`.

## Testing

- JVM unit tests for normalization, parsing, scoring and snapshot encoding. The matching corpus is generated from the device's MediaStore export.
- The Desktop Head Unit on the development machine for Android Auto, then the car.
- The voice log is the record of what Gemini actually sends.
- `PlayFromSearchActivity` replays any query and hints from adb, so resolution can be checked on a phone or emulator without a car.
- `adb shell cmd audio set-enable-hardening throw` for Android 17 background audio; `adb shell dumpsys media_session` for advertised actions.

## Milestones

1. **Skeleton.** Playback service with the audio-only player (trimmed renderer and extractor factories, offload), MediaStore scan, browse tree and search, voice log, parser and resolver with normalization, fuzzy matching, bigram tokenization and the title-track policy. Done: JVM unit tests pass; on an API 37 emulator replayed requests play FLAC, MP3, M4A and Ogg with the expected queue; on the phone through the Desktop Head Unit, Gemini's request reaches aamp with while-in-use status and, against the 7,612-track library, Gemini's garbled "and just for all my intelligents" plays "...And Justice For All" from track 1. Still to test in the car.
2. **Matching.** Thresholds and margins tuned against a corpus generated from the device's own library; digits and number words treated as equal; music in dot-prefixed folders detected.
3. **Performance.** Snapshot persistence, release signing, baseline profile, measurements against the budgets.
4. **Polish.** Artwork provider, queue persistence and resumption (resumption currently shuffles the library), genre requests, process exit reasons on the phone screen.
